# PDCA 운영 계획

이 문서는 한 번 작성하고 끝나는 명세가 아니라, 학기마다 운영 결과를 반영하는 기록이다. 각 주기의 Check 결과를 남기고 다음 Act를 새 Plan으로 연결한다.

## 프로젝트 목표

학생이 이메일 신청부터 `학번.dauswc.org` 서비스 확인까지의 과정을 문서만 보고 수행할 수 있게 하여, 신청 누락과 반복 문의를 줄인다.

## 역할

| 역할 | 책임 |
| --- | --- |
| 프로젝트 운영자 | 정책 결정, 문서 승인, VM 생성, Tailscale 초대, 배포 |
| 문서 관리자 | 절차 및 화면 변경 반영, 링크와 명령어 검증 |
| 학생 검증자 | 처음 이용하는 관점에서 문서대로 절차 수행 |
| 시스템 관리자 | DNS, VM, 네트워크, 향후 HTTPS 운영 |

한 사람이 여러 역할을 맡을 수 있지만, Check 단계에서는 가능하면 문서를 작성하지 않은 사람이 학생 검증자 역할을 맡는다.

## 1차 주기: 정적 안내 사이트

### Plan

목표:

- 개인정보를 수집하지 않는 정적 안내 사이트를 만든다.
- 기존 이메일 신청 절차를 유지한다.
- Tailscale 설치와 초대 수락의 혼란을 줄인다.
- VM 접속과 첫 서비스 배포까지 한 흐름으로 안내한다.

성공 기준:

- 전체 이용 절차가 첫 화면에 나타난다.
- 학생이 신청서, 이메일, Tailscale 계정 등 준비물을 알 수 있다.
- 주요 문서가 모바일에서 읽을 수 있다.
- 실제 VM에서 검증한 명령어만 게시한다.
- 웹사이트가 개인정보를 수집하지 않는다.

### Do

- 문서형 정적 사이트를 구축한다.
- 신청서 파일과 제출 안내를 등록한다.
- Tailscale 운영체제별 설치 문서를 작성한다.
- 초대 수락, 연결 확인, VM 접속 문서를 작성한다.
- 최소 서비스 배포 예제를 작성한다.
- `http://241110.dauswc.org`에 배포한다.

### Check

배포 전:

- 모든 내부 및 외부 링크를 확인한다.
- 신청서 파일이 내려받아지는지 확인한다.
- 예시 명령어를 테스트 VM에서 다시 실행한다.
- 개인정보 입력 폼과 분석 스크립트가 없는지 확인한다.
- 데스크톱과 모바일 화면을 확인한다.

운영 중:

- 학생 문의를 유형별로 기록한다.
- 학생이 가장 많이 중단하는 단계를 기록한다.
- 잘못된 계정 로그인, 초대 만료, 연결 실패 사례를 기록한다.
- 문서 오류와 실제 운영 정책의 불일치를 기록한다.

권장 측정값:

- 학기별 VM 신청자 수
- 신청자당 반복 문의 건수
- 신청서 보완 요청 건수
- Tailscale 관련 문의 건수
- 문서 오류 신고 건수

개인 식별 정보는 측정 기록에 포함하지 않는다.

### Act

- 반복 문의를 FAQ에 추가한다.
- 중단이 많은 단계의 설명과 이미지를 보강한다.
- 신청서에서 반복적으로 누락되는 항목의 예시를 개선한다.
- Tailscale 또는 서버 환경 변경을 반영한다.
- HTTPS 도입 가능성을 다음 학기 계획에서 재검토한다.

## 새 학기 시작 체크리스트

- 현재 학기와 담당자를 갱신한다.
- 신청서 양식과 이메일 주소를 확인한다.
- 기본 메모리, 디스크, 사용 기간 정책을 확인한다.
- Tailscale 공식 설치 링크와 화면을 확인한다.
- 초대 링크 정책과 만료 조건을 확인한다.
- VM 접속 명령과 배포 예제를 새 VM에서 테스트한다.
- DNS 규칙과 예시 주소를 확인한다.
- HTTPS 도입 여부와 보안 정책을 다시 검토한다.
- 이전 학기 문의를 반영했는지 확인한다.
