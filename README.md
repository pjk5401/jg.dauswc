# SW Cloud VM 이용 안내 사이트

학생들이 클라우드 VM 신청부터 서비스 배포까지의 과정을 스스로 따라갈 수 있도록 만든 정적 매뉴얼 사이트입니다.

이 프로젝트는 원래 웹 신청 및 승인 시스템으로 검토했으나, 현재 운영 환경에서 HTTPS를 제공할 수 없어 개인정보를 웹에서 수집하지 않는 방향으로 범위를 변경했습니다. 신청과 결과 안내는 기존 이메일 방식을 유지하고, 웹사이트는 절차와 문제 해결 방법만 제공합니다.

## 현재 목표

- 학생이 신청서 작성과 이메일 제출 방법을 이해할 수 있게 한다.
- Tailscale 설치, 로그인, 운영진 초대 수락 과정을 단계별로 안내한다.
- VM 생성 완료 후 접속 및 서비스 배포 방법을 안내한다.
- 학생 서비스 주소인 `http://학번.dauswc.org`의 사용 방법을 설명한다.
- 반복 문의와 신청 단계 누락을 줄인다.
- 개인정보, 신청서 내용, 로그인 정보를 웹에서 수집하거나 저장하지 않는다.

## 운영 흐름

1. 학생이 안내 사이트에서 신청서를 내려받아 작성한다.
2. 학생이 신청서를 운영진 이메일로 제출한다.
3. 학생이 Tailscale을 설치하고 신청 이메일과 동일한 계정으로 로그인한다.
4. 운영진이 Tailscale 초대 링크를 발송한다.
5. 학생이 초대를 수락한다.
6. 운영진이 학번을 VM ID로 사용해 VM을 수동 생성한다.
7. 운영진이 이메일로 생성 완료를 알린다.
8. 학생이 Tailscale을 통해 VM에 접속하고 서비스를 배포한다.
9. 학생이 `http://학번.dauswc.org`에서 서비스를 확인한다.

예시:

```text
교번 또는 학번: 241110
안내 사이트: http://241110.dauswc.org
학생 서비스: http://{학번}.dauswc.org
```

## 기본 VM 신청 기준

| 항목 | 기본값 |
| --- | --- |
| 메모리 | 1 GB |
| 디스크 | 10 GB |
| 사용 시작일 | 신청일 |
| 사용 종료일 | 신청일로부터 3개월 |
| 무기한 사용 | 신청서에서 별도 요청 |
| VM ID | 신청자 학번 |

CPU, 운영체제 등 나머지 항목은 운영 정책의 기본값을 사용합니다.

## 개발 및 배포

정적 문서 도구는 VitePress를 우선 후보로 선정했습니다. 아직 사이트 구현이 시작되지 않았다면 다음 작업은 [요구사항](docs/REQUIREMENTS.md)을 기준으로 VitePress 프로젝트를 구성하는 것입니다.

구현 후 이 절에 아래 정보를 반드시 추가합니다.

- 필요한 Node.js 버전
- 의존성 설치 명령
- 로컬 실행 명령
- 정적 빌드 명령
- VM 배포 경로와 웹 서버 설정
- 배포 및 되돌리기 절차

## 보안 원칙

현재 사이트는 HTTP로 제공되므로 다음 원칙을 지킵니다.

- 개인정보와 인증정보를 입력받지 않는다.
- 웹 로그인, 신청 폼, 관리자 페이지를 제공하지 않는다.
- 신청서 파일은 이메일로만 제출받는다.
- VM 비밀번호, 접속 토큰, Tailscale 초대 링크를 공개 문서에 기록하지 않는다.
- 실제 학생 정보는 저장소와 예제 화면에 포함하지 않는다.

HTTPS가 준비되더라도 신청 시스템 도입은 자동으로 결정하지 않습니다. 개인정보 최소 수집, 접근 권한, 보관 기간, 파기, 감사 기록을 다시 설계한 뒤 별도 PDCA 주기로 검토합니다.

## 프로젝트 관리

- 정책이나 범위가 바뀌면 `DECISIONS.md`에 이유와 영향을 기록합니다.
- 기능 요구사항이 바뀌면 `REQUIREMENTS.md`를 함께 갱신합니다.
- 학기별 점검 결과와 개선 활동은 `PDCA.md`에 누적합니다.
- 완료된 사용자 관점 변경은 `CHANGELOG.md`에 기록합니다.
- 비밀번호, API 키, 실제 신청서 및 개인정보는 Git에 커밋하지 않습니다.
