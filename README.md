# DAU Cloud Hub

학생들이 클라우드 VM 신청부터 서비스 배포까지의 과정을 스스로 따라갈 수 있도록 만든 정적 매뉴얼 사이트입니다.

이 프로젝트는 원래 웹 신청 및 승인 시스템으로 검토했으나, 현재 운영 환경에서 HTTPS를 제공할 수 없어 개인정보를 웹에서 수집하지 않는 방향으로 범위를 변경했습니다. 신청과 결과 안내는 기존 이메일 방식을 유지하고, 웹사이트는 절차와 문제 해결 방법만 제공합니다.

## 현재 목표

- 학생이 신청서 작성과 이메일 제출 방법을 이해할 수 있게 한다.
- Tailscale 설치, 로그인, 운영진 초대 수락 과정을 단계별로 안내한다.
- VM 생성 완료 후 접속 및 서비스 배포 방법을 안내한다.
- 학생 서비스 주소인 `http://학번.dauswc.org`의 사용 방법을 설명한다.
- 반복 문의와 신청 단계 누락을 줄인다.
- 개인정보, 신청서 내용, 로그인 정보를 웹에서 수집하거나 저장하지 않는다.

## 운영 흐름

1. 학생이 안내 사이트에서 신청서를 내려받아 작성한다.
2. 학생이 신청서를 DevWorks 운영진 이메일로 제출한다.
3. 학생이 Tailscale을 설치하고 신청 이메일과 동일한 계정으로 로그인한다.
4. 운영진이 Tailscale 초대 링크를 발송한다.
5. 학생이 초대를 수락한다.
6. 운영진이 학번을 VM ID로 사용해 VM을 수동 생성한다.
7. 운영진이 이메일로 생성 완료를 알린다.
8. 학생이 Tailscale을 통해 VM에 접속하고 서비스를 배포한다.
9. 학생이 `http://학번.dauswc.org`에서 서비스를 확인한다.
10. 사용 종료 후 학생이 사용 결과 보고서를 작성해 교수 박종규에게 제출한다.

예시:

```text
교번 또는 학번: 241110
안내 사이트: http://241110.dauswc.org
학생 서비스: http://{학번}.dauswc.org
```

## 양식 파일 위치

실제 HWP 파일은 다음 경로에 넣습니다.

```text
site/public/forms/vm-application.hwp
site/public/forms/vm-usage-report.hwp
```

- `vm-application.hwp`: VM 신청서
- `vm-usage-report.hwp`: 사용 결과 보고서

정적 사이트에서는 `/forms/파일명`으로 다운로드하게 됩니다. 실제 학생 정보가 작성된 문서는 이 저장소에 넣지 않습니다.

## 개발 및 배포

학생용 사이트는 `site/`의 VitePress 프로젝트로 구성되어 있습니다.

필요 환경:

- Node.js 20 이상 권장
- npm

로컬 실행:

```powershell
cd site
npm install
npm run dev
```

브라우저에서 `http://localhost:8080`으로 접속합니다.

정적 빌드:

```powershell
cd site
npm run build
```

빌드 결과는 `site/.vitepress/dist/`에 생성됩니다. 빌드 결과를 `8080` 포트에서 확인하거나 제공하려면 다음 명령을 사용합니다.

```powershell
cd site
npm run build
npm start
```

외부에서는 `http://서버주소:8080`으로 접속합니다. 장기 운영 시에는 정적 빌드 결과를 Nginx 등 웹 서버의 `8080` 포트로 제공하는 구성을 권장합니다.

### Ubuntu VM 운영 스크립트

저장소를 처음 복제한 뒤 실행 권한을 부여합니다.

```bash
cd ~/jg.dauswc/site
chmod +x cloud-hub.sh
```

의존성 설치, 빌드, 백그라운드 재시작을 한 번에 수행합니다.

```bash
./cloud-hub.sh deploy
```

자주 사용하는 명령:

```bash
./cloud-hub.sh start
./cloud-hub.sh stop
./cloud-hub.sh restart
./cloud-hub.sh status
./cloud-hub.sh logs
```

PID와 로그는 Git에 포함되지 않는 `site/.run/`에 저장됩니다. 기본 포트는 `8080`이며, 일시적으로 다른 값을 사용하려면 `PORT=포트번호 ./cloud-hub.sh start`처럼 실행할 수 있습니다.

운영 스크립트는 `site/serve.py`를 사용해 `/getting-started` 같은 VitePress clean URL을 해당 `.html` 파일에 연결합니다. 따라서 하위 페이지 주소를 직접 입력하거나 새로고침해도 정상적으로 열립니다.

운영 정책이나 서버 구성이 바뀌면 학생용 문서와 프로젝트 관리 문서를 함께 갱신합니다.

## 보안 원칙

현재 사이트는 HTTP로 제공되므로 다음 원칙을 지킵니다.

- 개인정보와 인증정보를 입력받지 않는다.
- 웹 로그인, 신청 폼, 관리자 페이지를 제공하지 않는다.
- 신청서 파일은 이메일로만 제출받는다.
- VM 비밀번호, 접속 토큰, Tailscale 초대 링크를 공개 문서에 기록하지 않는다.
- 실제 학생 정보는 저장소와 예제 화면에 포함하지 않는다.

HTTPS가 준비되더라도 신청 시스템 도입은 자동으로 결정하지 않습니다. 개인정보 최소 수집, 접근 권한, 보관 기간, 파기, 감사 기록을 다시 설계한 뒤 별도 PDCA 주기로 검토합니다.

## 프로젝트 관리

- 정책이나 범위가 바뀌면 `DECISIONS.md`에 이유와 영향을 기록합니다.
- 기능 요구사항이 바뀌면 `REQUIREMENTS.md`를 함께 갱신합니다.
- 학기별 점검 결과와 개선 활동은 `PDCA.md`에 누적합니다.
- 완료된 사용자 관점 변경은 `CHANGELOG.md`에 기록합니다.
- 비밀번호, API 키, 실제 신청서 및 개인정보는 Git에 커밋하지 않습니다.
